# DRST-Bench v1 模型标注复核网站

这是一个轻量级复核网站。它展示 `review_v3` 中通过自动规则检查和批判器筛选的候选状态事件；复核者检查模型结果，而不是从头标注原始样本。候选不会自动成为人工 gold。

## 使用方法

1. 使用服务器管理员分配的账号登录。
2. 从左侧选择任务，阅读完整对话；白色区域是对方发言，浅黄色区域是目标角色回复。
3. 右侧查看 Qwen3.6-27B 提议的状态变化。蓝色标记为前态证据，紫色标记为后态证据。
4. 对每条候选选择：
   - **保留**：前后状态、对象、边界、证据和评测问题均正确；
   - **修改**：变化明确且有价值，但部分字段需要调整；
   - **存疑**：当前证据不足以稳定判断，等待裁决；
   - **排除**：变化不成立或缺少评测价值。
5. 选择“修改”后，重新选择证据并填写精确原文短引文。
6. “保存复核草稿”允许部分完成；“提交并下一条”要求当前任务的全部候选均已处理。

前态和后态证据必须来自目标角色本人：前态严格早于变化轮次，后态必须包含变化轮次的目标回复。当前只使用 `post_response`，不使用 `unknown` 端点。方括号中的内心旁白不作为可观察证据。

## 标签含义

- `belief`：角色是否接受一个命题；
- `trust`：角色是否信任某个人；
- `commitment`：角色对某项行动的承诺程度；
- `emotion`：角色当前主要情绪，object 固定为 `self`。

## 数据和导出

管理员可以在网页右上角导出复核结果。SQLite 使用 WAL 模式，每次保存都记录 revision 和 payload SHA-256；草稿和正式提交保存在同一数据库，提交后仍可修订。

具体数据路径通过启动参数传入，绝不能提交到本仓库。典型参数包括：

```text
--data       trajectory JSONL
--events     review_v3 strict event JSONL
--db         review_v3 SQLite database
--auth       local users.json
--cert/--key local HTTPS certificate and private key
```

## 实现与安全

- Python 标准库 HTTP 服务，无额外 Web 框架依赖；
- PBKDF2 密码哈希、签名会话、HttpOnly/SameSite Cookie 和 CSRF 校验；
- HTTPS、SQLite WAL、乐观 revision 冲突检查和审计日志；
- 服务端校验 codebook、非 unknown 端点、目标角色证据、时间边界、精确短引文和评测字段；
- API 只返回复核必需的结构化候选，不返回模型原始输出、prompt 或其他隐藏字段。

长期公网使用时，建议配置域名、受信任 TLS 证书、反向代理访问日志和网络白名单。
